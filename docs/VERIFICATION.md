# 验证说明

本文提供测试范围与复现入口，不记录维护者的设备、账号、个人持仓或构建环境名称。历史测试结果不代表每个后续提交均已通过，也不等同于生产验收。

## 自动化检查

```sh
cd backend
python -m pytest -q
cd ../frontend
npm ci
npm test
npm run build
```

覆盖份额守恒、revision 冲突、交易时区与日历、报价过期、完整日线、AI 开关与输出校验、加密设置、通知重试/过期/去重、网络代理与错误脱敏。具体测试用例以当前源码为准，开发约束见 [开发规范](DEVELOPMENT.md)。

## 容器与发布检查

在独立临时数据卷上验证以下项目，不能使用真实部署数据做破坏性测试：

- 单容器网页与 worker 同时健康，访问口令生效，默认 AI 关闭。
- SQLite 及密钥重启后保留，网页或 worker 退出时容器能够失败退出。
- 数据目录初始化后降权运行，代码目录不可写。
- 卷权限、只读根文件系统、备份与恢复流程。
- amd64 / arm64 的镜像清单、实际拉取和启动；QEMU 结果只验证兼容性，不代表真实 ARM 性能。

各版本的镜像摘要与发布结果见 [发布核验记录](docker-release.json) 和 `releases/`。这些记录应对应其标明的版本，不应作为当前工作区通过测试的证明。

## 外部来源诊断

```sh
python scripts/probe_sources.py
python scripts/check_integrations.py
```

命令从仓库根目录执行。结果见 [来源探测](source-probe.json) 和 [集成检查](integration-check.json)。记录中的时间与状态仅表示当次探测；公开来源可能延迟、变更或失效，未知发布时间不得用采集时间冒充。

## 仍需部署环境验证

真实 AI / Webhook 账号与渠道联调、连续交易日的通知验收、外部 PostgreSQL 的备份恢复，需要相应配置与运行时间。完整收益回测未完成，不宣称策略有效或能够盈利。

报告问题时只提供版本、脱敏后的步骤和必要诊断；不要上传数据库、自选/持仓快照、完整日志、请求头、密钥或私有接口地址。
