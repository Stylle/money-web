# 开发规范

## 边界

`backend/app/crypto.py` 加密现货适配，`backend/app/providers.py` 股票行情适配，`news.py` RSS，`strategy.py` 确定性规则，`markets.py` 交易时间，`ai.py` AI 及输出校验，`services.py` 任务/通知，`main.py` API。模块不能绕过统一网络校验读取外部 URL。
`news_sources.py` 只适配公开标题/短摘录与原文链接，不绕过访问验证；`source_health.py` 持久化健康状态及退避。未知发布时间必须保留为空，不能用采集时间冒充。主备 Yahoo 节点不是两个独立机构。
前端 React + TypeScript，主要页面由独立组件函数组织。只通过 `/api` 调用后端，密钥不进入 localStorage，访问口令只用 sessionStorage。

## 数据规则

- UTC 存储，市场时区调度，北京时间展示。严禁以服务器当地日期判断美股交易日。
- 份额校验使用 Decimal，最多两位小数，持仓及现金恰好合计 100。
- 持仓是手动快照，不能默默按照行情重估；保存必须带 revision，冲突返回 409。
- 价格必须是有限正数，OHLC/成交量校验，K 线须有序唯一。当前日线不得参与技术建议。
- 报价早于市场开盘、超过五分钟、未来超过 30 秒、数据源错误时，不给份额建议。
- 切换来源不得刷新旧报价时间，不得逐行混合不同复权口径的日线。报价、日线和分时的来源分别保留；只有价格线点时不能伪造 OHLC。
- 日线至少 65 根并覆盖上一交易日；未知或过期日历暂停信号，不用工作日猜测替代。
- 修改规则必须增加规则版本并说明行为变化。AI 不能覆盖现金/仓位限制或程序风险禁买。
- 不把技术指标打分包装成上涨概率，不宣称经过回测的收益，除非实际完成相应验证。

## 任务与通知

数据库租约避免同时执行同类任务。事件和通知 outbox 同事务插入；接收端应按 Idempotency-Key 去重。
网络发送最多只能做到“至少一次”：远端收到但本地未记录时可能重发，不宣称 exactly-once。
静默期间暂缓发送，超过 expires_at 丢弃。API 和 worker 使用同一数据库和加密密钥卷。

## 质量检查

```powershell
cd backend
python -m pytest -q
cd ../frontend
npm ci
npm test
npm run build
```

测试应覆盖持仓守恒、并发修改、交易时区、节假日、AI 越界和失效、压缩响应解码、通知重试/过期/去重，避免仅复述实现。
依赖通过 requirements.lock / package-lock.json 固定；增加依赖后更新锁文件并检查 Linux 镜像兼容性。Python 锁中保留跨平台 colorama；无仅 Windows 可用的运行依赖。
Docker 入口仅在初始化专用数据目录时使用 root，随后清空附加组并 setgid/setuid 到 PUID/PGID，再 exec 容器管理器；网页、worker、健康检查均以非 root 身份运行，只写数据卷和 /tmp。任何真实密钥、数据库、日志、构建依赖目录不得提交或打入源码包。

v0.1 通过建表初始化数据库。后续修改已有表结构前必须引入版本化迁移，先备份，不允许用删库替代迁移。

加密资产仅接入现货市场观察，不放置订单。市场标识 CRYPTO，代码须为 BASE-USD 或 BASE-USDT，类型 crypto。两种计价币严格区分，报价与前日收盘同交易所，完整 UTC 日线不得混接；每日观察 UTC 00:30（北京时间 08:30），周末不休市。

## 单容器与部署文档约定

默认一个容器，由 `app.container` 管理网页和 worker 两个进程；任一退出即停止另一进程并退出，交由 Docker 重启。SQLite 使用 WAL、30 秒锁等待和文件所有权锁；容器独占同一数据库后才清理遗留任务租约。外部 PostgreSQL 不清理全局租约。监控独立心跳与网页共同参与健康检查。
发布说明和 Docker Hub Overview 均先给最小带注释 Compose，再说明必填口令、持久数据、更新、备份和可选参数。不要求新用户部署独立数据库或 worker 容器，不自动转换已有 PostgreSQL 数据。

v0.2.1 初始化只处理专用数据目录及已知 SQLite 文件/密钥，保留内容，不递归处理其他文件，拒绝符号链接、硬链接及系统目录。不得通过永久 root 运行规避卷权限错误；启动错误只记录阶段、异常类型、errno 与数字 UID/GID，不记录原异常正文、数据库 URL 或密钥。

镜像内应用代码及网页资源由 root 持有，运行 UID 不可写，避免运行进程篡改下一次重启的初始化代码。
